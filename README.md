# 噪声监测数据站 · 六年级第5课

完整课堂应用《连续变化的数据》（信息科技六年级《过程与控制》第二单元“数据运算有逻辑”第5课）。延续第4课“校园系统探索站”的结构：学生端、教师大屏、本地数据库（Node 内置 SQLite）、六年级名单与可搬迁资源；不需要实时AI、外网素材或3D运行库。

## 上课入口

双击 `启动课堂.command`（需要 Node.js 22.13 或更新版本），或在本目录运行 `npm start`。

- 教师大屏：`http://localhost:8796/teacher`，也可用教师电脑自己的局域网 IP 打开 `http://教师电脑IP:8796/teacher`。免密码。
- 学生入口：同一局域网访问终端显示的 `http://教师电脑IP:8796/`（启动时自动列出，不写死IP）。
- 端口 8796，与第4课的 8794 不冲突，两课可以同时开着。如需改端口：`PORT=8800 npm start`。

教师页、教师测试模式 `/test`、答案和班级数据接口默认只接受教师电脑自身地址的请求，学生设备打开会得到 403；学生页面不出现教师或测试入口。若教师要用另一台设备（如平板）看大屏，按部署需要设置允许地址：`TEACHER_ALLOW=192.168.1.23 npm start`（多个用逗号隔开，可写网段如 `192.168.1.0/24`；网段越大，学生越可能进入教师页，请按实际教室网络选择）。

## 学生端（沉浸版，2026-10-10 重做）：今晚，你是小区噪声巡查员

学生不再面对表单式页面，而是扮演“小区噪声巡查员”（Kenney CC0 卡通角色，可点 HUD 头像换男/女角色），和向导小递一起走在**夜晚小区地图**上（与《导入》页同一画风）。五关是小区里的五个地点，第六个地点“巡查报告站”是20题考核。

**焦点引导（解决“学生不知道点哪里”）**：任何时刻只有一个发光的主要操作（金色按钮 + 脉动光圈），旁边贴一句话提示和指示小手；其余按钮都是低调的次要样式或暂时隐藏。底部小递气泡给完整一句说明和刚才操作的反馈。右上角 **?** 按钮：再给一级提示（观察 → 思路 → 具体帮助，计入提示次数）并用聚光灯压暗其他区域几秒，照亮当前该点的地方。喇叭按钮开关音效（默认关）。“减少动态效果”系统设置下，所有动画关闭，功能不变。

每个地点内是三步：**想一想**（情境 + 一句问题 + 2—3张大选项卡，先预测才能做实验）→ **做实验**（场景里只亮出当前要操作的控件，结果自动保存，两枚“证据徽章”点亮后出现“说清楚 →”）→ **说清楚**（一张卡一个问题，选完自动翻下一张）：①**对照预测**：并排显示“我的预测/我的实验结果”，判断是否一致；②**用我的数据**：题干里是自己测到的数值，选出能被这些数据支持的理由；③概念卡；④**新情境**迁移题；最后“检验我的解释”。检验前不显示对错；不通过时对不上的卡片标红，写明**针对所选误解、引用本人数据**的反馈，已选错的选项划掉；迁移题答错换成等价的另一个新情境。通过后用两次点选完成句块“我看到……，所以我认为……”，再回地图。

**证据星（2026-10-10 逆向设计审计后新增）**：每站3颗——★通过本站；★第一次检验时解释卡全部与证据一致；★在此基础上第一次检验时迁移题也答对（逐级，迁移三选一单独答对可能是猜的）；首次检验前用了第3级“具体帮助”的，后两颗不计。HUD 显示 ⭐ x/15，地图徽章显示每站星数。积分照旧（每站10分，只说明完成）。目标—证据—判据—动作的完整对齐与审计发现的漏洞见 `docs/逆向设计对齐表.md`。

| 地点（关卡） | 做实验（结果自动保存） | 说清楚（提交后判定） |
|---|---|---|
| 1 广场监测器（数据在哪里流动） | 点声音卡“夜深人静”/“小声聊天”/“广场舞音乐”，广场上的人、监测屏数字和“监测器透视”三格（输入—计算—输出）同步变化，超标时屏幕泛红 | 对照预测；证据卡（自己测到的“dB > 55 → 超标”）；输入/计算/输出三卡；迁移：电热水壶 / 智能路灯 |
| 2 声音记录亭（波形与散点） | 点红色录音键录10秒，同时左右拖动音量推杆（或选教师现场/本机麦克风）；录完在两个圆点之间点一下读数 | 对照预测；证据卡（“你在t秒读到v”）；曲线为何更合适；迁移：气温 / 心率估中间值 |
| 3 3号楼小明家（生活中的连续量） | 拖动窗帘把手看光照表与曲线（≥8个不同读数）；开始烧水，在途中“读水温” | 对照预测；证据卡（光照max→min经过n个读数）；7张数据卡；迁移：车速表 / 气球放气 |
| 4 物业控制室（阈值） | 回放同一晚噪声曲线；红线就是阈值，可拖滑块或直接在图上拖红线；先55 dB运行，再换明显不同的阈值运行，报警灯随回放闪烁 | 对照预测；证据卡（55 dB→a次、x dB→b次）；阈值在哪个环节；4张案例卡找阈值；迁移：自动门 / 空调 |
| 5 屋顶种植园（迁移设计） | 依次选①传感器测什么 ②何时开水泵 ③阈值（未选好前不出现下一步，不预先替学生选），运行4天；植物叶片随湿度变蔫/变绿 | 对照预测；证据卡（自己成功方案的湿度范围）；阈值作用、调高的后果；迁移：鱼缸加热棒 / 温室遮阳帘 |

实验证据要求、服务端复算、积分去重与第一版相同；“说清楚”的卡片、判据和证据记录在逆向设计审计后重做（`rules.js`、`activities.mjs`、新增 `cards.mjs`）。焦点高亮只指向操作（控件或整组选项），从不指向某个答案；选项顺序按学生打乱。每站10积分，同一轮只记一次；错误不扣分。地图上未完成前一站时后一站上锁；“巡查报告站”随时可进，但五站完成后才高亮。菜单（☰）里有“本站实验记录”“再看一次本站情境”“本站重新做实验”“切换学生”。

素材与许可见 `docs/素材来源.md`（Kenney Toon Characters 与 Interface Sounds，CC0；其余为原创SVG）。`public/` 全部约 0.5 MB，离线可用；角色姿势图用到时才加载，音效首次播放时才加载。

20题考核与通关积分分开：40题库按5项目标各8题，每次每目标抽4题、选项顺序打乱。提交前可改答案、页面列出未答题号且不显示对错；提交后错题在前，逐题显示自己的选择、正确答案和解析。可“再考一次 · 新抽20题”，服务端保留每次成绩（教师端显示首次和最近）。考后选做“阈值调校挑战”（5个需求→拖动阈值，不计分）。

## 现场数据与仿真边界

- 第1、3、4、5关和第2关的“模拟推杆”都是教学仿真数据，图上标注“仿真”。噪声单位 dB 只用于仿真。
- 麦克风只计算相对响度（0—100），不是分贝，不录音、不上传音频。第2关可选“观察教师现场”（读取教师大屏广播的现场响度）或“本机麦克风”。
- 教师大屏底部“全班一起观察：教室噪声监测”（教材拓展与提升）：开启教师机麦克风，拖动现场阈值，超过阈值时提示并计数；局域网HTTP页面会弹出 localhost 授权小窗（与第4课相同方式），需允许弹窗。

## 教师大屏与隔离测试（图表版）

`/teacher` 为1920×1080投影设计（标签≥17px、粗条形，1366宽自动改两列），手写SVG/HTML图表、无第三方库、离线可用。顶部选班级（601—606），每5秒自动刷新；无数据的图显示“尚无证据”。

| 图表 | 内容与口径 |
|---|---|
| 关键数字 | 名单人数、已进入、完成五站、平均证据星、已考核、考核平均（首次→最近） |
| ① 五站进度 | 每站已完成/进行中/未开始堆叠条（分母=本班名单）；点一站，下方明细只看该站未完成者 |
| ② 各站目标：第一次 vs 最终 | 每站“首次解释就与证据一致”“迁移首答正确”“最终通过”百分比（分母=该站已提交人数） |
| ③ 常见误解（首次检验） | 横向条形，写出误解原话；红=仍存在、浅绿=已纠正；点一条显示是哪些同学（并筛选明细） |
| ④ 预测→实验后的转变 | 每站：预测就符合 / 预测不同→实验后修正 / 预测不同→还没修正 |
| ⑤ 想法提示使用 | 每站说清楚环节用到的最高提示级别（没用/观察/思路/具体帮助） |
| ⑥ 20题考核 | 分数分布直方图（首次/最近）+ 按目标正确率 |
| ⑦ 实时动态 | 最近30分钟每分钟的记录数、其中提交检验数、通过一站的人数 |
| ⑧ 第4站阈值气泡图 | 同学们试过的阈值 × 提示次数，气泡大小=人数，虚线=规则曲线，红虚线=55 dB |
| ⑨ 第5站浇水方案 | 每个“湿度·降到阈值”方案的4天湿度范围竖线，绿=保持在30%—70% |

下方：五站诊断与建议（未纠正误解 + 追问建议）、学生明细（每站证据星、误解数、考核首次/最近）与“查看证据”（每站首次预测、尝试次数、首次解释/迁移首答与最终、提示级别、首次误解与仍存在的误解、句块）。

**演示数据**：大屏右上“看演示数据”（`/teacher?demo=1`）读取 `public/demo-class.json`——由 `tools/seed-demo-class.cjs` 用虚构名单（601班40人，姓名均带“（虚构）”）在临时数据库中经真实接口生成，不连接正式数据，不自动刷新，“开启新轮次”禁用。重新生成：`node tools/seed-demo-class.cjs /tmp/某临时目录 --export public/demo-class.json`，用完删掉临时目录。与教师页一样只限教师设备访问。

大屏接口为减轻每5秒刷新的体积只发摘要（去掉曲线原始点、逐题考核内容）；“导出班级记录”请求 `full=1`，导出完整记录。

“进入教师测试模式”（`/test`）用虚构身份自由选站（地图上所有地点都可进入，顶部黄色工具条），可看本关标准操作与答案、载入达标示例、查看40题答案、试做20题测试卷、直接试玩考后挑战；全部只存在本页，不写入班级数据。`/demo` 是无身份演示，同样不保存。“开启本班新轮次”保留旧轮记录，新轮重新计进度与积分，旧轮待同步记录不会覆盖新轮。教师可“导出班级记录”（JSON）。学生端不设额外的导出模块。

## 保存、备份与迁移

课堂数据在 `runtime/classroom.sqlite`。服务重启后保留进度、首次预测、首次/最近提交与考核历史。断网时记录先存本机（按身份和轮次隔离），恢复后自动补传并去重；状态栏显示“未同步”时尚未进入大屏。备份：先停止服务，再复制整个 `runtime/`。迁移：复制整个应用目录（含私有 `roster.json` 与备份），安装 Node 22.13+ 后 `npm start`。

名单：`roster.json` 已从六年级名单导入 314 人（601—606），ID 规则与第4课相同（同一学生在两课的 ID 一致）。`roster.json` 与 `runtime/` 不在 public 目录、学生网页无法下载，并已列入 .gitignore；公开示例用 `roster.example.json`（虚构姓名）。更新名单：`python3 tools/import-roster.py /路径/六年级班级姓名名单.xlsx`（需 openpyxl）。
